# 启动后日历自动定位修复

> 后续状态：首帧后 `jumpTo` 仍会造成可见的短暂位移，已进一步改为 `initialScrollOffset` 首帧定位。当前实现见 `docs/vibe/2026-10-23_13-14-21-日历首帧无滚动定位优化.md`。

## 需求与范围

- 修复 App 从启动倒计时页进入日历主页后，没有自动滚动到当前日期的问题。
- 仅调整日历页首次显示时的定位逻辑。
- 不改变“回到当前日期”按钮、月份下拉定位、周卡片视图、缩放或日期选择行为。

## Flutter 官方实现基线

- `WidgetsBinding.addPostFrameCallback`：<https://api.flutter.dev/flutter/widgets/WidgetsBinding/addPostFrameCallback.html>
- `WidgetsBinding.endOfFrame`：<https://api.flutter.dev/flutter/widgets/WidgetsBinding/endOfFrame.html>
- `ScrollController.jumpTo`：<https://api.flutter.dev/flutter/widgets/ScrollController/jumpTo.html>
- `SliverFixedExtentList`：<https://api.flutter.dev/flutter/widgets/SliverFixedExtentList-class.html>

采用 Flutter 官方的首帧结束回调获取已建立的 `ScrollPosition`，然后使用 `jumpTo` 一次性设置初始滚动位置。

项目适配点：当前月标题高度、月底间距、每月周数和日历行高均已知，因此复用项目现有 `_monthOffsetForDate` 直接计算当前日期的 offset，不需要依赖懒加载的 `todayKey` 先被创建。

## 修改前

`CalendarPageState.initState` 在首帧结束回调中调用 `_revealKey`：

```text
addPostFrameCallback
  └─ _revealKey(todayKey, ...)
       └─ await endOfFrame
```

`_revealKey` 进入后再次等待 `endOfFrame`。此时已处于 post-frame 阶段，而 Flutter 不会为这次等待自动请求新帧。启动页的倒计时在进入主页后已取消，没有其他帧时，定位逻辑会停在等待状态。

详细根因见：`docs/vibe/2026-10-23_12-44-07-启动后日历未自动定位当前日期排查.md`。

## 修改后

`CalendarPageState.initState` 仍在首帧结束后定位，但改为：

1. 确认 State 仍已挂载且 `ScrollController` 已连接到滚动位置。
2. 使用 `_monthOffsetForDate(now, alignment: .2)` 直接计算今日所在日历行的目标 offset。
3. 使用 `minScrollExtent` 和 `maxScrollExtent` 限制目标范围。
4. 使用 `scroll.jumpTo(target)` 在启动时无动画定位。

新的调用链是：

```text
addPostFrameCallback
  └─ 计算今日 offset
       └─ clamp 到有效滚动范围
            └─ jumpTo
```

## 修改内容与原因

### `lib/calendar_page.dart`

- 移除首屏 post-frame 回调中对 `_revealKey(todayKey, ...)` 的调用。
- 增加 `scroll.hasClients` 保护。
- 复用已有 `_monthOffsetForDate` 计算当前日期位置。
- 对 offset 做边界限制后直接 `jumpTo`。

原因：消除 post-frame 回调内再等待下一帧的时序依赖，并避免首屏定位依赖 Sliver 懒创建的 `todayKey.currentContext`。

## 可能影响与注意事项

- 首次进入日历主页时会直接显示当前日期附近，不显示滚动动画，与原有 `animate: false` 意图一致。
- 当前日期仍使用 `DateTime.now()`，未改变时区或日期判定规则。
- 修复依赖现有日历项目高度为可确定值；若未来将月标题或日历行改为动态未知高度，需同步调整 `_monthOffsetForDate`。
- 本次未修改计划卡片或日历日详情卡片，不影响跨页卡片一致性。
- 工作区中原有 `lib/stats_page.dart` 修改与本次无关，本次未触碰该文件。

## 验证说明

按项目协作约束，本次未执行构建、编译、打包、静态分析、格式化或任何自动化测试。

建议用户手动验证：

- 等待 5 秒自动进入主页时，日历是否定位到今天。
- 点击“开始规划”提前进入主页时，日历是否定位到今天。
- 切换不同日历行高后重新冷启动，今天所在行是否保持在视口约 20% 位置。
- 年初和年末日期是否正确受滚动边界限制。
