# 计划与联系人分类导入导出及条件导出

## 任务目标

- 将设置页原有的计划导入导出拆分为“导出计划数据”、“导出联系人数据”、“导入计划数据”和“导入联系人数据”四个独立入口。
- 两个导出入口归于同一组，两个导入入口归于同一组。
- 导出支持全量或按条件导出；导入不增加筛选条件。
- 计划和联系人 XLSX 中的主键 ID 均保留用于再次导入匹配，但默认隐藏并锁定。

## 修改前情况

- “表格与数据”页只有计划 XLSX 的直接导出和导入入口。
- 点击导出后立即导出全部计划，无法按年度、日期、状态或其他业务字段限定范围。
- 联系人没有独立 XLSX 模板、导出服务、导入解析和预览流程。
- 计划 ID 已有隐藏和锁定处理，但联系人还没有对应模板。

## 成熟方案调研

### 业务产品参考

- HubSpot 从当前视图导出记录，使用“全部记录”视图表示全量导出：<https://knowledge.hubspot.com/import-and-export/export-records>
- Notion 允许导出当前视图或默认视图，视图筛选决定数据集：<https://www.notion.com/help/export-your-content>
- Notion 视图支持属性过滤以及 AND/OR 高级筛选：<https://www.notion.com/help/views-filters-and-sorts>
- Google Contacts 支持导出单个、多个选中联系人或全部联系人：<https://support.google.com/contacts/answer/7199294?co=GENIE.Platform&hl=en>
- Todoist 按项目限定 CSV 导出范围：<https://www.todoist.com/help/articles/208821185-Project-templates>

### Flutter 官方实现参考

- 使用 `showModalBottomSheet` 与可滚动子项展示导出条件：<https://api.flutter.dev/flutter/material/showModalBottomSheet.html>
- 使用 `SegmentedButton` 在两个互斥的导出范围之间切换：<https://api.flutter.dev/flutter/material/SegmentedButton-class.html>
- 使用 `showDateRangePicker` 选择计划导出日期区间：<https://api.flutter.dev/flutter/material/showDateRangePicker.html>
- 使用 `FilterChip` 处理标签、联系人等可见的多选筛选：<https://api.flutter.dev/flutter/material/FilterChip-class.html>
- 使用 `FilledButton` 表示确认导出主操作：<https://api.flutter.dev/flutter/material/FilledButton-class.html>
- 使用 `Wrap` 处理窄屏下的按钮和多选项自动换行：<https://api.flutter.dev/flutter/widgets/Wrap-class.html>

### 项目适配点与无法直接照搬之处

- ClPlan 设置页不存在 HubSpot/Notion 式的当前数据视图，因此不能直接导出“当前视图”；适配为点击导出后在底部面板中选择“全量导出 / 按条件导出”。
- 计划是起止日期区间，不是单日记录；“2026 年计划”采用计划区间与筛选区间有交集即命中的规则，防止遗漏跨年计划。
- 不同类型条件之间使用 AND；同一类型的多个标签或联系人使用 OR，降低移动端高级逻辑编辑的理解成本。
- XLSX 隐藏列和单元格保护不是 Flutter UI 能力，联系人模板沿用项目现有的 OOXML ZIP/XML 后处理方案。

## 修改后情况

### 设置页入口

- “导出”分组下放置“导出计划数据”和“导出联系人数据”。
- “导入”分组下放置“导入计划数据”和“导入联系人数据”。
- 较宽窗口双列展示同组操作，较窄窗口自动换行。

### 计划导出

- 支持全量导出。
- 按条件导出默认使用当前年度的 1 月 1 日至 12 月 31 日，可修改或清除日期限制。
- 支持计划名称/内容关键词、日期区间相交、完成状态、分类、进度方案、进度节点、标签和联系人条件。
- 底部固定显示实时命中数量，命中为零时禁用确认导出。

### 联系人导出

- 支持全量导出。
- 按条件导出可在姓名、电话和备注中搜索关键词，并可手动多选最终联系人范围。
- 关键词与手动选择同时存在时使用 AND。

### 联系人 XLSX 与导入

- 新增“联系人”工作表，字段为联系人 ID、姓名、电话和备注。
- 联系人 ID 列默认隐藏并锁定，其他列在工作表保护下仍可编辑。
- 有 ID 的行按主键更新，无 ID 的行生成新主键并新增；导入不删除其他本地联系人。
- 导入前显示新增、更新和警告数量。
- 检查必填姓名、备注长度、文件内重复 ID 以及导入后的姓名+电话重复。

## 修改内容与原因

- `lib/settings_page.dart`
  - 拆分四个入口，新增计划和联系人导出条件面板以及联系人导入预览。
  - 使用官方 Material 组件保持移动端交互一致性，并避免直接导出无法确认数据范围。
- `lib/xlsx_service.dart`
  - 新增联系人工作簿生成、文件选择、解析、行级警告与 OOXML 主键列保护。
  - 保持计划和联系人两类模板独立，避免导入时互相依赖。
- `lib/app_controller.dart`
  - 新增按 ID 查找联系人与批量导入联系人的业务验证/保存入口。
  - 统一处理姓名、电话、备注的前后空白与重复性。

## 可能影响与注意事项

- 按条件导出只决定写入 XLSX 的数据行；填写说明中的分类、进度、标签和联系人参考选项仍来自 App 当前全量配置，便于在导出文件中继续新增数据。
- 导入更新联系人配置不会反向改写已保存计划和任务中的联系人快照。
- 工作表保护用于防止常规误编辑，不等同于文件加密；修改 XLSX 内部 XML 的工具仍可绕过保护。
- 当前项目的单文件导入上限为 50 MB，数据行上限为 10000 行；计划和联系人使用相同上限。
- 按项目约束，本次未执行构建、编译、格式化、单元测试、集成测试、端到端测试或其他自动化验证，需由用户手动验证界面、筛选口径、XLSX 保护和导入结果。
