# 统计页 `dateOnly` 方法缺失修复

## 问题现象

Xcode 调用 Flutter 构建时，`lib/stats_page.dart` 中多处 `dateOnly(...)` 调用被报告为未定义方法，导致 `kernel_snapshot_program` 生成失败。

## 修改前的情况

- `dateOnly(DateTime date)` 是 `lib/task_widgets.dart` 中的顶层日期格式化函数，输出 `yyyy-MM-dd` 格式文本。
- `lib/stats_page.dart` 仍在统计周期文本、任务筛选、统计分桶和自定义日期筛选界面中调用该函数。
- 统计页近期调整移除了对 `task_widgets.dart` 的导入，导致该顶层函数在当前库作用域中不可见。
- `analysis_options.yaml` 没有排除 `lib/**`，并启用了 `package:flutter_lints/flutter.yaml`。

## 修改后的情况

- `lib/stats_page.dart` 恢复导入 `task_widgets.dart`。
- 原有 `dateOnly(...)` 调用重新指向项目现有的统一实现。
- 未改变日期字符串格式、统计逻辑、界面布局或交互行为。

## 修改内容

在 `lib/stats_page.dart` 的本地文件导入区增加：

```dart
import 'task_widgets.dart';
```

## 修改原因

这是修复当前错误所需的最小变更。将日期方法迁移到新的公共工具文件会同时影响多个页面，超出本次“修复缺失方法”的必要范围，因此本次不进行额外重构。

## Flutter / Dart 官方依据

- Dart 官方 `undefined_method` 诊断说明：当方法名未定义或在当前作用域不可见时，Analyzer 会产生该诊断；常见修复方式是定义该方法或改为可见的既有方法：<https://dart.dev/tools/diagnostics/undefined_method>
- Dart 官方 `dart analyze` 文档：命令行静态分析与支持 Dart 的 IDE / 编辑器使用相同的静态分析能力：<https://dart.dev/tools/dart-analyze>
- Flutter 官方命令行文档：`flutter analyze` 用于分析项目 Dart 源代码：<https://docs.flutter.dev/reference/flutter-cli>

## 静态检查结论

该问题可以被静态代码检查发现，属于编译前即可确定的名称解析错误，并非只能在 Xcode 构建时发现的问题。如果此前没有提示，常见原因包括：

- 修改后没有执行 `flutter analyze`；
- IDE 打开的目录不是实际 Flutter 工程根目录 `v2`；
- IDE 的 Dart Analysis Server 尚未刷新或处于异常状态；
- 检查流程只执行了格式化或 lint 子集，而没有执行完整 Analyzer 分析。

## 可能影响与注意事项

- 本次恢复了统计页对 `task_widgets.dart` 的编译期依赖；这是修改前已有的依赖关系。
- `dateOnly` 当前位于组件文件中，从架构角度可在后续独立任务中迁移到公共日期工具文件，但不影响本次修复的正确性。
- 按项目协作约束，本次未运行构建、编译、打包、静态分析或自动化测试；需由用户手动验证。
