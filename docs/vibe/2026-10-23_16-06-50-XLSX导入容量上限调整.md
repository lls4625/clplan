# XLSX 导入容量上限调整

## 任务目标

将计划和联系人 XLSX 的单文件导入上限从 10 MB、5000 行调整为 50 MB、10000 行，以覆盖更大的年度数据量。

## 修改前情况

- 计划和联系人的导入文件超过 10 MB 时拒绝解析。
- 工作表包含超过 5000 行数据时拒绝导入；首行表头不计入数据行。
- 计划模板的分类、进度、四象限、日历显示和提醒下拉验证只覆盖到第 5001 行。
- 页面说明显示“10 MB、5000 行”。

## 官方实现基线

- Dart `File.readAsBytes()` 官方 API：<https://api.dart.dev/dart-io/File/readAsBytes.html>
- Dart `Uint8List` 官方 API：<https://api.dart.dev/dart-typed_data/Uint8List-class.html>

项目仍沿用 Dart 官方文件 API 将选中文件读取为字节数组，再交给现有 XLSX 解析器。Flutter 官方不提供 XLSX 解析组件，本次不更换现有 `excel` 解析链路，仅调整业务保护阈值及对应模板范围。

## 修改内容

- 在 `XlsxService` 中统一定义 50 MB 和 10000 行两个导入常量。
- 计划和联系人导入共用新的文件大小上限。
- 计划和联系人的数据行上限统一调整为 10000；第 1 行仍作为表头，因此工作表最多为 10001 行。
- 计划模板的数据验证区域同步扩展到第 10001 行。
- “表格与数据”页面的限制说明同步更新。

## 修改后情况

- 单个 XLSX 文件不超过 50 MB 时可进入解析。
- 单个计划或联系人工作表最多可导入 10000 行数据。
- 导出的计划模板在 10000 行数据范围内保留原有下拉和数据验证能力。

## 原因

- 50 MB、10000 行能够覆盖更大的年度计划数据，减少用户手工拆分文件的需求。
- 将阈值统一为常量，避免计划与联系人导入限制分散定义。
- 同步扩展模板数据验证范围，避免第 5001 行以后缺失下拉校验。

## 影响与注意事项

- `readAsBytes()` 会先将文件完整读入内存，XLSX 解压和工作簿解析还会产生额外内存开销；50 MB 是业务保护阈值，不是实际峰值内存。
- 10000 行导入会增加预览列表、冲突处理和数据库逐条写入时间，建议由用户在真机上手动验证大文件的内存与耗时。
- 本次不改变导入合并规则、主键匹配规则或 XLSX 字段结构。
- 按项目约束，本次未执行构建、编译、打包或自动化测试。
