# XLSX 主键隐藏锁定与中文列设置

## 需求与结论

- 表格列设置界面只显示中文名称，不再展示 `id`、`status` 等内部字段名。
- “唯一 ID”和“状态 ID”属于内部字段，新安装及数据库升级后默认不显示。
- 计划 XLSX 继续保留“计划 ID”作为导入主键，但该列在工作表中隐藏并锁定。
- 再次导入导出的模板时，有计划 ID 的行按主键匹配现有计划，无计划 ID 的行作为新增计划；未出现在文件中的本地计划不删除。

## 修改前

- “表格列显示与顺序”同时显示中文标签和英文内部字段名。
- `table_columns` 初始化时所有字段均默认可见，已有数据库也不会自动隐藏唯一 ID、状态 ID。
- XLSX 的“计划 ID”列可见且可直接编辑。
- 导入逻辑已经是逐行新增或同 ID 合并，并未执行全量覆盖或删除，但界面与模板说明没有明确这一点。

## 官方资料与项目适配

Flutter 界面继续采用官方 Material 组件：

- Flutter `SwitchListTile`：<https://api.flutter.dev/flutter/material/SwitchListTile-class.html>
- Flutter `ListTile`：<https://api.flutter.dev/flutter/material/ListTile-class.html>

项目适配点：`SwitchListTile.title` 保留中文字段标签，移除可选的 `subtitle`，不改变官方组件的排序和开关交互。

Flutter 官方不提供 XLSX 工作表保护或隐藏列 API。项目现有实现已使用 `excel` 生成工作簿，并直接补充 OOXML 数据验证，因此本次沿用同一技术路径，以 Microsoft Open XML 文档为格式依据：

- 工作表保护：<https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.sheetprotection>
- 单元格锁定属性：<https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.protection>
- 隐藏列属性：<https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.column>

无法直接照搬之处：Microsoft 文档示例面向 Open XML SDK，而当前 Flutter/Dart 项目没有使用该 SDK；因此在现有 XLSX ZIP/XML 后处理阶段写入等价的列隐藏、单元格保护和工作表保护节点。

## 修改后与修改内容

### 中文列设置

- 移除内部 `keyName` 副标题，只保留中文 `label`。
- 导入预览的新增计划列表不再显示内部计划 ID。
- 保留现有 `ReorderableListView` 和 `SwitchListTile` 交互。

### 默认隐藏内部字段

- 数据库版本由 11 升至 12。
- 新建数据库初始化列配置时，将 `id` 和 `status` 的 `visible` 设为 `0`。
- 旧数据库升级时同步将这两个字段设为不可见。

### XLSX 主键保护

- “计划”工作表的 A 列“计划 ID”继续导出，但设置为隐藏。
- 启用工作表保护；A 列保持默认锁定，B 列至其余业务字段使用未锁定样式，仍可正常填写。
- 禁止受保护状态下修改列格式，避免直接取消隐藏主键列。
- “填写说明”明确主键匹配、新增规则和增量导入规则。
- 新增说明行后，同步调整说明表标题样式行及下拉选项命名范围起始行。

## 导入行为核对

- 空计划 ID：解析时生成新的内部 ID，因此视为新增。
- 已存在的计划 ID：进入冲突预览，默认保留本地字段，仅合并用户勾选的导入字段。
- 不存在的非空计划 ID：作为新增计划保存。
- 导入流程只保存本次新增或合并的计划，不遍历删除本地计划，因此再次导入不会删除本地数据库中的其他内容。

## 可能影响与注意事项

- “状态 ID”是旧任务状态的内部键，用户在 App 表单中不能直接编辑；当前计划 XLSX 不包含任务状态 ID 列，因此没有额外新增无业务含义的状态列。
- 工作表保护用于防止常规误编辑，不等同于加密；具备文件结构修改能力的工具仍可能绕过保护。导入端仍以计划 ID 是否存在为主键判定依据。
- 不同表格软件对 OOXML 工作表保护与数据验证的支持程度可能不同，Microsoft Excel 的兼容性通常最好。
- 按项目约束，本次未执行构建、编译、格式化、单元测试、集成测试或端到端测试，需要用户手动验证导出文件的隐藏列、锁定状态和再次导入结果。
