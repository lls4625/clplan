# 查询与统计抽屉移除所属计划筛选

## 需求

排查并移除项目中的全部“所属计划”下拉框。计划数量持续增加后，下拉选项会过长，查找成本和渲染内容都会随计划总量增长，不适合作为长期筛选入口。

## Flutter 官方资料

- [Drawer](https://api.flutter.dev/flutter/material/Drawer-class.html)：抽屉继续沿用 Flutter Material 官方 `Drawer` 结构，本次只删减其中一个筛选项，不改变抽屉打开、关闭和滚动方式。
- [DropdownButtonFormField](https://api.flutter.dev/flutter/material/DropdownButtonFormField-class.html)：现有分类、进度方案和进度节点仍使用 Flutter 官方表单下拉组件；“所属计划”不再适合以枚举全部计划的下拉方式呈现，因此将该控件完整移除。
- [FilterChip](https://api.flutter.dev/flutter/material/FilterChip-class.html)：标签筛选继续沿用官方筛选组件，不受本次调整影响。

项目适配点：本项目原先从全部现存计划和历史计划 ID 动态生成“所属计划”下拉项。官方组件能够承载下拉选择，但不会解决选项随业务数据无限增长带来的可用性问题，因此本次不替换组件，而是取消该筛选维度。

## 修改前

- `TaskSearchCriteria` 保存 `planId`，任务列表会按所属计划 ID 过滤。
- 任务查询抽屉枚举全部现存计划，并补充已经不存在的历史计划 ID。
- `StatCriteria` 保存 `planId`，统计中的任务和计划数据集都会按该 ID 过滤。
- 统计条件抽屉同样枚举全部现存计划和历史计划 ID。

## 修改后

- 任务查询抽屉不再显示“所属计划 / 全部计划”下拉框。
- 统计条件抽屉不再显示“所属计划 / 全部计划”下拉框。
- 两套条件模型均移除 `planId`，对应的数据过滤分支也同步删除，避免出现界面上无法查看或清除、实际仍在生效的隐藏条件。
- 分类、进度方案、进度节点、标签、关键字、日期和统计对象等既有条件保持不变。

## 修改内容与原因

### `lib/tasks_page.dart`

- 从 `TaskSearchCriteria` 的构造参数、字段和生效判断中删除 `planId`。
- 从查询条件更新方法中删除 `planId` 传递。
- 删除任务列表按所属计划过滤的逻辑。
- 删除任务查询抽屉的所属计划下拉控件及计划选项生成逻辑。

原因：完整枚举计划会使选择列表长度随数据量增长，并且移除界面后必须同步取消条件状态，保证查询行为透明。

### `lib/stats_page.dart`

- 从 `StatCriteria` 的构造参数、字段和 `copyWith` 中删除 `planId`。
- 删除任务统计集合和计划统计集合按所属计划过滤的逻辑。
- 删除统计条件抽屉的所属计划下拉控件及计划选项生成逻辑。

原因：统计条件不再提供所属计划选择，统计结果应只由仍可见的条件决定。

## 影响与注意事项

- 用户不能再从这两个抽屉按单一所属计划筛选任务或统计结果。
- 计划和任务数据本身的 `planId` 关联未修改；任务详情中的“所属计划”也未修改。
- 全量检索后，任务详情页还存在一处“所属计划”文字，但它是只读的 `WorkValueField`，用于说明当前任务归属，并非下拉框，因此保留。
- 计划主页的“查询条件”抽屉原本没有“所属计划”字段，本次未改动其其他筛选项。
- 本次没有修改数据库结构，不涉及数据迁移。
- 按项目约束未执行构建、编译或自动化测试，需由用户手动验证抽屉布局和筛选结果。
